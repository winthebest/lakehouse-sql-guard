# Kaggle leak cases: frozen checker v0.2.0, secondary variant (placeholder temporal table)

**Secondary run, not an evaluation of the cases as authored.** The primary result (`20261107-6bc64b8`) stands unchanged: every spec was rejected. Here each spec is rewritten the way the real-world dbt specs are: the label table is removed from `time_columns` and a placeholder temporal table that no query reads (`unused_placeholder_events: occurred_at`) is declared instead. Nothing else changes. Registered in commit 8ccd88f.

Specs the checker still rejects: kl03, kl06, kl07, kl16. Registered limitation: the checker no longer knows the label table holds history, so same-table windows and aggregates may be invisible to it; a miss may come from the workaround as much as from the rules.

Run `20261107-2c5b6f4-variant` of `bench/kaggle/evaluate.py` at 2c5b6f4. Registration: `bench/kaggle/eval-prereg.yaml` (commit 93f0876). Cases digest `447490465518759c`, checker `src/sqlguard` tree `5e260ebc75d0`.

Thresholds (frozen): static 0.425, replay 0.003968, combined 0.475; verdict threshold 0.5. Intervals: 95% cluster bootstrap by case, 2000 resamples, seed 42. Replay runs use the CLI defaults (24 prediction times, sampling seed 0).

Rules: `verdict:*` counts a query detected when the checker says leaky (static run, or the run with replay); `threshold:*` applies the frozen thresholds to the static score, the replay mismatch rate and the combined score. A query that errored has no score and is not detected. An unverifiable query keeps the checker's score. "As misses" counts unverifiable, error and static-only runs as not detected even when their score reaches the threshold.
